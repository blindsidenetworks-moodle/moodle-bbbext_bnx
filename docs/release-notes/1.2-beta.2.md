# 1.2-beta.2 (July 2, 2026) — Open LMS code review #2 remediation log

Remediation release for the eight findings raised in Open LMS Code Review #2
(June 2026): four performance/correctness findings, three security findings, and
one minor cleanup. Each finding was resolved in a single, self-contained commit
per the remediation prompt's one-commit-per-finding rule.

This document is the per-finding remediation log that supplements the top-level
`RELEASENOTES` and `CHANGES` entries for `1.2-beta.2`.

## Finding mapping

- **OL2-3.1.1** — `9ac2556`
  - Added `defined('MOODLE_INTERNAL') || die();` to `lib.php` immediately after
    the file docblock.

- **OL2-3.1.2** — `3833673`
  - Rewrote `reminders_utils::replace_vars_in_text()` to accumulate the full
    `$search`/`$replace` arrays and run a single `str_replace()` after the loop,
    so an earlier substitution's output can no longer be re-matched by a later
    placeholder.

- **OL2-3.1.3** — `7f1136b`
  - Imported `mod_bigbluebuttonbn\logger` in `classes/meeting.php` so the
    `join_meeting()` default `$origin = logger::ORIGIN_BASE` resolves to the
    parent-module constant instead of a non-existent `bbbext_bnx\logger`.

- **OL2-3.1.4** — `d9ba1a1` (Operator decision: Option A)
  - Added a `pix/i/bell.svg` fallback for the `bbbext_bnx:i/bell` entry declared
    in the `lib.php` icon map.
  - Declared the `bbbext_bnx_reminders_guests` table (email, userfrom,
    isenabled) in the privacy provider metadata, with matching lang strings.
  - The parent-module fixture failures noted in the review are recorded as an
    upstream dependency (see `.copilot/reference/BNX_UPSTREAM_DEPS.md`) rather
    than adding test-only branching to production code.

- **OL2-3.2.1** — `f751cb7` (Operator decision: Option A)
  - Signed reminder unsubscribe links with a per-row HMAC token
    (`subscription_utils::get_unsubscribe_token()`), verified with `hash_equals()`
    in `subscription.php` before any subscription state change.
  - Note: core provides no `moodle_url::sign()`, so the review's explicitly
    endorsed per-row HMAC mechanism was used. This preserves Option A's intent
    (a signed token in the URL, no schema change, one-click UX retained).

- **OL2-3.2.2** — `8e48457`
  - Switched the subscription toggle form to `method="post"` with a `{{sesskey}}`
    hidden field, exposed `sesskey` through the output class, and enforced
    `require_sesskey()` in `managesubscriptions.php` before the write.

- **OL2-3.2.3** — `e9014a9`
  - Read `originpage` with `PARAM_ALPHA` and validated it against an explicit
    `['view', 'index']` allow-list in `import.php`, falling back to `view`, to
    prevent an open redirect.

- **OL2-4.1.1** — `94c13e3`
  - Added inline comments to the previously empty `db/upgrade.php` savepoints at
    `2026050102` and `2026050103` explaining why each version bump exists.

## Validation summary

- All edited PHP files pass with no reported errors.
- New lang strings for the privacy metadata table are present in
  `lang/en/bbbext_bnx.php`.
- No schema change was required; `version.php` is bumped to `2026070200`
  (`1.2-beta.2`) with a matching no-op upgrade savepoint.
